# 一起做裙子

静态网页小游戏，入口为 `tailor.html`。从仓库根目录启动静态文件服务后访问 `/games/tailor/tailor.html`。

## 本轮调整

原有流程的问题是：有五道工序，但没有明确制作目标，操作几乎不影响分数。裁剪初始化还会覆盖塑形，返回和刷新时的状态也不完整。

- 增加三份轮换委托，显示目标色彩、轮廓示意、尺寸和符合度。示意图用于提示风格，不是工程纸样。
- 裁剪纸样来自当前裙身轮廓。沿绿色虚线剪裁，覆盖至少 85% 后展开即可进入缝纫；偏离纸样影响精度和成衣外形，重置可以重新挑战。
- 缝纫按住加速、松开减速，35%—55% 为低速区。质量按实际车线距离加权，不再给固定高分。支持鼠标、触摸和踏板聚焦后的空格/回车。
- 综合评分为目标符合度 40%、裁剪 30%、缝纫 30%，影响起拍价和星级。不按委托制作也能完成作品，但符合度较低。
- 归一化保存裁片，保留刷新、改变窗口尺寸和走秀往返后的作品；未完成工序不能跳过，成交按作品编号去重。
- 工坊、走秀和拍卖共用裙身轮廓生成规则；增加纵向细分，保留微风前的褶皱形状，并缓存面料纹理。

## 验证

`tests/playthrough.cjs` 使用 Playwright。启动本地服务、让 Node 能找到 Playwright 后运行：

```sh
node tests/playthrough.cjs
```

默认网址为 `http://127.0.0.1:8765/games/tailor/`，可通过 `TAILOR_URL` 修改；`CHROME_PATH` 可指定浏览器位置。

测试覆盖真实鼠标沿线裁剪、手机尺寸、刷新恢复、键盘踏板、重置、60/120Hz 缝纫对比、走秀往返和重复结算。缝纫质量对比采用固定时间步模拟，其余主要流程使用浏览器交互；截图输出到系统临时目录。

## 后续优先级

1. **提升裙子的辨识度**：独立领口、肩带、袖型与裙片结构。目前仍是旋转轮廓网格加褶皱，并非真实布料模拟，不能表现所有服装结构。
2. **完善成长节奏**：按章节配置委托、面料与配饰解锁；目前新增的是三份轮换委托，旧的历史手记和章节内容尚未全面重做。
3. **丰富表达与收藏**：统一三处场景中的配饰表现，补充更多款式，以及走秀页直接收藏、不拍卖的独立流程。

图标依赖外部 Iconify 服务；Three.js 优先读取仓库已有版本，失败后尝试 CDN。尚未验证真实手机硬件和浏览器间的全部兼容性。
